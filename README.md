# 3. Concept

## 3.1 서비스 컨셉

책다듬이는 단순한 독서 기록 서비스를 넘어 사용자의 지속적인 독서 활동을 유도하고, 독서 과정에서 발생하는 독후 활동과 성취를 하나의 서비스에서 관리하는 것을 목표로 한다.

### 사용자 보상 체계

- D-day
- 독서율(%)
- 일일 / 주간 퀘스트
- 독서 활동에 따른 경험치
- 레벨 시스템
- 재화 및 재화 상점
- 서재 꾸미기
- 레벨에 따른 기능 해금
- 독후 활동
- 재독서 및 과거 기록 비교

# 4. Main Domain

## 4.1 독서

사용자의 실제 독서 활동을 관리한다.

- 독서 시간
  - 타이머 시작
  - 일시정지
  - 종료
  - 독서 시간 누적
- 독서율
  - 현재 읽은 페이지
  - 전체 페이지
  - 독서 진행률 계산
- 독서 기록
  - 책별 독서 상태
  - 독서 시간
  - 읽은 페이지
- 독서 인증
  - 페이지 촬영
  - 이미지 등록
  - 페이지 수 기록
- 다회독
  - 이전 독서 기록 보존
  - 새로운 독서 기록 생성
  - 과거 독서와 현재 독서 비교

# 5. Business Logic

## 5.1 독서 인증

사용자의 실제 독서 활동을 인증한다.

```text
페이지 촬영
    ↓
이미지 등록
    ↓
페이지 정보 기록
    ↓
독서 기록 갱신
```

## 5.2 독서 중 활동

독서 중 사용자가 인상적인 문장을 저장할 수 있다.

```text
독서 중
  ↓
인상적인 문장 저장
  ↓
문장 모음집
```

문장 모음집에서는 다음 기능을 제공한다.

- 문장 저장
- 문장 수정
- 문장 삭제
- 문장 조회

## 5.3 완독 후 활동

완독 이후 독후 활동을 수행할 수 있다.

### 독후감

- 독후감 작성
- AI 기반 피드백
- 독후감 수정
- 독후감 삭제
- 독후감 조회

### 평점

- 책에 대한 평점 등록
- 평점 수정
- 평점 조회

### 한줄평

- 한줄평 작성
- 한줄평 수정
- 한줄평 삭제
- 한줄평 조회
- 스포일러 표시
- 블라인드
- 좋아요

# 9. API Design

REST API를 기반으로 기능별 Endpoint를 설계한다.

예시:

```text
/api/users
/api/books
/api/reading-records
/api/reading-sessions
/api/quotes
/api/reviews
/api/quests
/api/rewards
/api/shop
```

HTTP Method를 통해 리소스에 대한 작업을 구분한다.

```text
GET     /api/books
POST    /api/books
GET     /api/books/{bookId}
PUT     /api/books/{bookId}
DELETE  /api/books/{bookId}
```
