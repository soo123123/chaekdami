# 0010 · 작업을 시작할 때 main 업데이트 알림

- 상태: 채택 · 2026-11-24 · 결정: FE1

## 예전 설계
세션 시작 알림(H4)은 known-issues 변경과, 스펙 브랜치에서 내 파일이 main에서 먼저 바뀐 것만 알려줬다 ([0008](./0008-known-issues-on-main.md)).

## 바꾼 이유
- 다른 파트가 main에 올린 코드는 known-issues를 건드리지 않으면 알림에 나오지 않았다. PR 없이 올라온 변경을 나중에야 알게 된 일이 있었다.
- 내 브랜치가 얼마나 뒤처졌고, 합치면 충돌하는지 작업자가 직접 확인해야 했다.

## 지금 방식
- `scripts/harness/main-news.py`가 지난 확인 이후 main에 올라온 커밋을 요약한다: 내가 고친 파일과 겹침 → 합치면 충돌 → 공용 파일 → 파트별(내 파트 먼저) → 커밋 → PR 없이 올라온 것으로 보이는 커밋 → 받는 명령.
- **합치지 않는다.** 충돌은 `git merge-tree`로 가상 확인만 하고, 받을지는 작업자가 정해 직접 실행한다 (AGENTS 7장).
- known-issues만 바뀐 커밋은 세지 않는다 (`known-issues.py news`가 알린다).
- 확인 시점은 각자 컴퓨터의 `.git/main-news-seen`에만 저장한다. 같은 소식은 다시 알리지 않고, `--all`로 다시 볼 수 있다.
- Claude Code는 H4가 세션 시작·재개 때 자동으로 실행한다. Cursor와 터미널에서는 직접 실행한다.

## 영향
- 바뀐 도구: `main-news.py`(새로 추가), `session-news.py`(H4)
- 한계: 세션을 켜 둔 동안 올라온 것은 다시 실행해야 보인다. 충돌은 커밋한 것 기준이고, 충돌이 없어도 동작이 깨질 수 있다. PR 없는 커밋은 병합 기록과 제목으로 추정하며 막지 않는다.
