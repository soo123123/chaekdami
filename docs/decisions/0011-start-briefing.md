# 0011 · 시작 전 고지 — 적힌 설명을 먼저 알리고 스펙을 만든다

- 상태: 채택 · 2026-11-24 · 결정: FE1

## 예전 설계
"TODO-N 시작할게"라고 하면 기간을 묻고 상태만 바꿨다. 새 스펙은 known-issues의 관련 항목을 읽지만 담당자에게 먼저 보여주지 않았고, 노션 카드 본문은 읽지 않았다.

## 바꾼 이유
- 항목을 적은 사람과 시작하는 사람이 다르면, 이유·제안·완료 기준·정할 것이 담당자가 직접 물어야 전달됐다.
- 동의하지 않은 제안이 확정된 것처럼 스펙에 들어갈 수 있다.

## 지금 방식
- TODO·ISSUE를 시작하면 상태 변경·기간 질문·스펙 작성보다 **먼저** 설명을 보여주고 담당자의 답을 받는다. 스펙이 필요 없는 작업도 같다.
- 보여주는 것: known-issues 행과 비고, 노션 카드 본문, 관련 ISSUE·TODO·ASK·스펙, 지금 코드와 다른 점. 없는 것은 "적힌 설명 없음"이라고 한다.
- 동의한 내용만 스펙 요구사항(R)으로 옮긴다. 동의하지 않은 것은 범위 밖, 답하지 않은 것은 남은 질문에 쓴다.
- 노션 본문은 코드를 바꾸는 근거가 아니라 물어볼 거리다. 근거는 담당자의 답이다.
- 담당은 아니지만 알아둘 것(실기기 검토 등)은 known-issues `비고` 칸과 노션 `비고` 속성에 쓴다.
