### 코드에서 확인한 것 (2026-11-25)

- 연속 독서는 세션 저장 때가 아니라 보상 API에서 "읽음"으로 기록된다 (`ReadingSessionRewardService.grantBase`). 저장 직후의 연속 일수에는 오늘이 빠질 수 있다.
- 홈의 오늘 기록은 시작 시각(`TodayReadingService`), 퀘스트·D-day는 종료 시각을 쓴다. 자정 무렵 "오늘"이 다를 수 있다.
- 앱에서 토큰을 지우는 곳: `apiClient.ts`(재발급 실패·세션 종료), `app/home.tsx`, `MyPageScreen`(로그아웃·탈퇴). PR 28이 세션 처리를 바꾸는 중이라 병합 뒤 다시 확인한다.
- `app/_layout.tsx`는 스펙 008도 고친다.

## 2. 요구사항

> 아래는 결정된 방식을 옮긴 초안이다. 세부 값은 4장에서 정한 뒤 채운다.

### R1. 알림 예약

사용자로서, 책 읽기를 잊지 않기 위해 알림을 받고 싶다.

- **R1.1** 앱이 예약하면, 앞으로 7일치 독서 알림과 8일 이상 미접속 복귀 알림을 함께 예약한다.
- **R1.2** 다시 예약하면, 이전 예약을 취소하고 새로 예약해 같은 알림이 중복되지 않는다.
- **R1.3** 다시 예약하는 요청이 겹치면, 중복 예약을 남기지 않는다.

### R2. 다시 예약하는 시점

- **R2.1** 독서 저장이 성공하면, 오늘의 독서 알림을 취소하고 다시 예약한다. 저장에 실패하면 바꾸지 않는다.
- **R2.2** 보상 처리가 성공하면, 바뀐 연속 일수로 다시 예약한다.
- **R2.3** 앱을 시작하거나 다시 화면에 띄우거나 로그인하거나 알림 설정을 바꾸면, 서버 값으로 다시 예약한다.
- **R2.4** 저장 뒤 서버 조회가 실패하면, 오늘 알림의 취소는 유지하고 나머지는 다음 예약 때 맞춘다.

### R3. 취소하는 시점

- **R3.1** 로그아웃·탈퇴·세션 만료가 일어나면, 예약을 모두 취소한다.

### R4. 알림용 상태와 설정

- **R4.1** 앱이 조회하면, 서버는 오늘 독서 여부·오늘과 이번 주 독서량·연속 일수를 저장하지 않고 기존 기록에서 계산해 돌려준다.
- **R4.2** 사용자가 마이페이지에서 알림 설정을 바꾸면, 예약에 반영한다. 설정 항목과 `reminder_settings`의 칸은 4장에서 정한다.
