# 010 · 닉네임 변경 API — Requirements

## 1. 배경

- 서버에 닉네임 변경 서비스(`NicknameChanger`, `UserService.changeNickname`)가 있지만 부르는 API가 없다 ([TODO-34](../../known-issues.md#todo-34)).
- `/api/me`에는 조회(GET)와 탈퇴(DELETE)만 있다 ([user/api](../../domains/user/api.md)).
- 가입 때의 닉네임 규칙은 2~16자, 영문·숫자·한글, 대소문자 무시 중복 불가, 비밀번호와 같으면 불가다 ([user/rules §1](../../domains/user/rules.md#1-가입-정보)).
- 지금 변경 서비스는 트랜잭션 안에서 비밀번호(BCrypt)를 비교해 그동안 DB 연결을 쥔다. 로그인은 ISSUE-BUG-8에서 이 문제를 고쳤다.
- 사람 결정 (2026-11-25, BE3): TODO-34 중 API만 만든다. 앱 화면은 FE2 몫으로 남긴다. 주소는 `PATCH /api/me`, 응답은 `GET /api/me`와 같다. 비밀번호 재입력과 변경 횟수·기간 제한은 없고, 로그인은 유지하며, DB 구조는 바꾸지 않는다.

## 2. 요구사항

### R1. 닉네임 변경

사용자로서, 다른 이름으로 보이기 위해 닉네임을 바꾸기를 원한다.

- **R1.1** 로그인한 사용자가 `PATCH /api/me`로 새 닉네임을 보내면, 앞뒤 공백을 뺀 값으로 저장하고 200과 바뀐 내 정보(`GET /api/me`와 같은 형식)를 돌려준다.
- **R1.2** 지금과 같은 닉네임을 보내면, 성공으로 응답한다. 대소문자만 바꾼 닉네임도 저장된다.
- **R1.3** 닉네임을 바꾸면, 이미 받은 Access Token과 Refresh Token은 그대로 쓸 수 있다.
- **R1.4** 닉네임을 바꾸면, 커뮤니티의 이전 글에도 새 닉네임이 작성자로 보인다.

### R2. 거절

- **R2.1** 로그인하지 않고 부르면, `401`로 응답한다.
- **R2.2** 닉네임이 없거나, 앞뒤 공백을 뺀 길이가 2~16자가 아니거나, 영문·숫자·한글이 아닌 글자가 있으면, `400 VALIDATION_ERROR`로 응답한다.
- **R2.3** 다른 사용자가 쓰는 닉네임이면 (대소문자 무시), `409 NICKNAME_ALREADY_EXISTS`로 응답한다.
- **R2.4** 새 닉네임이 자기 비밀번호와 같으면, `400 VALIDATION_ERROR`로 응답한다.
- **R2.5** 두 사용자가 동시에 같은 닉네임으로 바꾸면, 한 명만 성공하고 다른 한 명은 `409 NICKNAME_ALREADY_EXISTS`를 받는다.
- **R2.6** 거절하면, 닉네임을 바꾸지 않는다.

### R3. 동시 처리

- **R3.1** 비밀번호를 비교하는 동안, DB 연결을 쥐지 않는다.
- **R3.2** 비교하는 동안 비밀번호가 바뀌거나 탈퇴·정지됐으면, `401`로 응답하고 닉네임을 바꾸지 않는다.
- **R3.3** 닉네임 변경이 비밀번호 변경·정지와 겹쳐도, 그 변경을 옛 값으로 되돌리지 않는다.

### R4. 문서

- **R4.1** 구현이 끝나면, `docs/domains/user/`에 API와 규칙이 반영되고 `backend/http/`에 요청 예시가 있다.
