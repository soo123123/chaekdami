# 003 · 세션 문장 저장과 삭제 데이터 정리 — Requirements

## 1. 배경

- 독서 종료 때 앱은 세션 저장(`POST /api/reading-sessions`) 뒤에 문장 API(`POST /api/reading-records/{id}/sentences`)를 **한 번 더** 불러 문장을 저장한다. 두 요청이 따로라서 세션만 저장되고 문장은 빠질 수 있다. 서버에는 세션 요청의 `sentence` 필드와 저장 메서드 `SentenceService.recordFromSession`이 이미 있지만 쓰이지 않는다.
  - 더 큰 문제: 문장 저장만 실패하면 앱은 저장 전체를 실패로 보여주고, "다시 시도하기"를 누르면 세션을 **한 번 더** 저장한다 → 같은 독서가 세션 2건이 된다. → [known-issues L1-1](../../known-issues.md) → [known-issues L1](../../known-issues.md)
- 책을 서재에서 지우면 세션·회차·책만 지워지고, 그 책의 문장·리뷰·독후감·좋아요·신고가 남는다. 정리 메서드 `ReviewCleanupService.deleteAllOfBook`도 이미 있지만 부르지 않는다. → [known-issues L2](../../known-issues.md)
- 회원 탈퇴 시 review·reward·dday 데이터는 지워지지만 reading 데이터(서재·회차·세션)는 남는다. → [known-issues L3](../../known-issues.md)

세 가지 모두 "이미 있는 기능끼리 연결이 빠진 것"이라 규모가 작고, 독서(BE1)와 독후활동(BE3) 두 파트에 걸친다.

## 2. 요구사항

### R1. 세션 저장 때 문장 저장

사용자로서, 독서 종료 화면에서 적은 문장이 따로 저장하지 않아도 문장 모음에 남기를 원한다.

- **R1.1** 세션 저장 요청에 `sentence`가 있으면, 세션이 붙은 회차의 문장으로 저장한다.
- **R1.2** `sentence`가 없거나 공백뿐이면, 문장을 만들지 않고 세션만 저장한다.
- **R1.3** 문장 규칙(1~500자)을 어기면, 세션도 저장하지 않고 400 `VALIDATION_ERROR`로 응답한다.
- **R1.4** 세션 저장이 실패하면, 문장도 저장되지 않는다.
- **R1.5** 세션 저장으로 만든 문장은 오늘 문장 수(`GET /api/me/reading-today`의 `memoCount`)에 포함된다.

### R2. 책 삭제 시 독후활동 정리

사용자로서, 서재에서 책을 지우면 그 책에 남긴 기록이 함께 사라지기를 원한다.

- **R2.1** 책을 삭제하면, 그 책의 문장·리뷰·독후감과 그 리뷰의 좋아요·신고도 삭제한다.
- **R2.2** 정리 중 하나라도 실패하면, 책 삭제 전체가 취소된다 (일부만 지워지지 않는다).
- **R2.3** 다른 사용자가 같은 ISBN 책에 남긴 리뷰·좋아요·신고는 지우지 않는다.

### R3. 회원 탈퇴 시 서재 정리

사용자로서, 탈퇴하면 내 서재와 독서 기록도 모두 지워지기를 원한다.

- **R3.1** 회원 탈퇴 시, 그 사용자의 책·회차·세션을 모두 삭제한다.
- **R3.2** 탈퇴가 실패하면, reading 데이터도 지워지지 않는다 (기존 리스너와 같은 트랜잭션).

## 3. 범위 밖

- 세션 요청의 `photos` 저장 (독서 인증 스펙에서)
- 문장 저장 시 쪽 번호 받기 (세션 문장은 쪽 번호 없이 저장 — 현재 메서드 규칙 유지)
- 앱 수정 범위는 ❓ 질문 2에서 정한다
- 책 삭제 시 보상 데이터(`reading_session_rewards`, `reward_transactions`) 정리

## 4. 남은 질문 (❓)

1. 책 삭제 시 **보상 내역**(세션별 보상 기록)도 지워야 하나? 현재는 남는다: `reading_session_rewards`와 `reward_transactions`가 지워진 세션 번호를 가리킨 채 남고, 이미 받은 경험치·재화는 그대로다. (현재 범위 밖으로 둠)
2. R1이 되려면 앱(FE1)이 세션 저장 요청에 `sentence`를 **넣어 보내고**, 그 뒤 문장 API를 **따로 부르던 것을 빼야** 한다 (`features/fe1/api/readingApi.ts`). 둘 중 하나만 바뀌면 문장이 두 번 저장되거나 빠진다. 앱 수정을 이 스펙에 포함할까, FE1에 따로 맡길까? (순서: 서버 먼저, 앱 나중)
3. R1.3: 문장이 규칙을 어기면 세션까지 실패시키는 게 맞나, 아니면 세션은 저장하고 문장만 버릴까? 참고: 앱 입력칸이 500자로 막혀 있고 공백뿐인 문장은 보내지 않아서, 실제로 규칙 위반이 생길 일은 거의 없다.
