# 003 · 세션 문장 저장과 삭제 데이터 정리 — Requirements

## 1. 배경

- 독서 종료 때 앱은 세션 저장(`POST /api/reading-sessions`) 뒤에 문장 API(`POST /api/reading-records/{id}/sentences`, 쪽 번호 = `endPage`)를 **한 번 더** 불러 문장을 저장한다. 두 요청이 따로라서 세션만 저장되고 문장은 빠질 수 있다. 서버에는 세션 요청의 `sentence` 필드와 저장 메서드 `SentenceService.recordFromSession(userId, readingRecordId, sentence, pageNumber)`가 이미 있지만 쓰이지 않는다. → [ISSUE-BUG-2](../../known-issues.md#issue-bug-2)
  - 더 큰 문제: 문장 저장만 실패하면 앱은 저장 전체를 실패로 보여주고, "다시 시도하기"를 누르면 세션을 **한 번 더** 저장한다 → 같은 독서가 세션 2건이 된다. → [ISSUE-BUG-1](../../known-issues.md#issue-bug-1)
- 책을 서재에서 지우면 인증·세션·회차·책만 지워지고, 그 책의 문장·리뷰·독후감·좋아요·신고가 남는다. 정리 메서드 `ReviewCleanupService.deleteAllOfBook`도 이미 있지만 부르지 않는다. → [ISSUE-DATA-1](../../known-issues.md#issue-data-1)
- 회원 탈퇴 시 review·reward·dday 데이터는 지워지지만 reading 데이터(서재·회차·세션·인증)는 남는다. → [ISSUE-DATA-2](../../known-issues.md#issue-data-2)
- 스펙 004로 세션 저장 때 통과한 독서 인증이 세션에 연결된다 (`certifications.reading_session_id`). 세션 저장 한 번에 세션·인증 연결·(이 스펙의) 문장이 함께 처리된다.

세 가지 모두 "이미 있는 기능끼리 연결이 빠진 것"이라 규모가 작고, 독서(BE1)·독후활동(BE3)·앱(FE1)에 걸친다.

사람 결정 (2026-11-22):
- 책 삭제 시 보상 내역 정리는 이 스펙에서 하지 않는다 ([ASK-4](../../known-issues.md#ask-4)로 따로).
- 앱 수정(FE1)을 이 스펙에 포함한다. 서버와 앱 중 하나만 바뀌면 문장이 두 번 저장되거나 빠지기 때문이다.
- 문장이 규칙을 어기면 세션도 저장하지 않는다 (앱에서 문장은 필수라 함께 실패하는 게 일관적).
- 문장 AI 검증은 하지 않는다. 문장 규칙은 지금처럼 "비어 있지 않음, 500자 이하"뿐이다.

## 2. 요구사항

### R1. 세션 저장 때 문장 저장 (서버)

사용자로서, 독서 종료 화면에서 적은 문장이 세션과 함께 한 번에 저장되기를 원한다.

- **R1.1** 세션 저장 요청에 `sentence`가 있으면, 세션이 붙은 회차의 문장으로 저장한다.
- **R1.2** 문장의 쪽 번호는 세션의 `endPage`로 한다. `endPage`가 1 미만이면 쪽 번호 없이 저장한다 (지금 앱 동작과 같음).
- **R1.3** `sentence`가 없거나 공백뿐이면, 문장을 만들지 않고 세션만 저장한다.
- **R1.4** 문장 규칙(공백 제외 1자 이상, 500자 이하)을 어기면, 세션도 저장하지 않고 400 `VALIDATION_ERROR`로 응답한다.
- **R1.5** 세션·문장·인증 연결(스펙 004)은 한 번에 처리된다. 하나라도 실패하면 셋 다 저장·연결되지 않는다. 그래서 앱이 다시 시도할 때 같은 인증 번호를 다시 쓸 수 있다.
- **R1.6** 세션 저장으로 만든 문장은 오늘 문장 수(`GET /api/me/reading-today`의 `memoCount`)에 포함된다.

### R2. 앱이 한 번만 저장 요청 (FE1)

사용자로서, 저장이 실패해 다시 시도해도 같은 독서가 두 번 기록되지 않기를 원한다.

- **R2.1** 앱은 독서 종료 저장 때 세션 저장 요청에 `sentence`를 넣어 보내고, 문장 API(`POST /api/reading-records/{id}/sentences`)는 **따로 부르지 않는다**.
- **R2.2** 세션 저장이 실패하면(문장 규칙 위반 포함) 지금처럼 오류를 보여주고, "다시 시도하기"는 같은 요청을 한 번 다시 보낸다. 서버가 저장하지 않았으므로 세션이 2건이 되지 않는다.
- **R2.3** 앱 배포 순서는 서버 먼저, 앱 나중이다. 서버만 바뀐 상태에서 옛 앱(문장을 따로 저장)이 써도 문장이 두 번 저장되지 않는다 (옛 앱은 세션 요청에 `sentence`를 보내지 않으므로).

### R3. 책 삭제 시 독후활동 정리 (서버)

사용자로서, 서재에서 책을 지우면 그 책에 남긴 기록이 함께 사라지기를 원한다.

- **R3.1** 책을 삭제하면, 그 책의 문장·리뷰·독후감과 그 리뷰의 좋아요·신고도 삭제한다.
- **R3.2** 정리 중 하나라도 실패하면, 책 삭제 전체가 취소된다 (일부만 지워지지 않는다).
- **R3.3** 다른 사용자가 같은 ISBN 책에 남긴 리뷰·좋아요·신고는 지우지 않는다.

### R4. 회원 탈퇴 시 서재 정리 (서버)

사용자로서, 탈퇴하면 내 서재와 독서 기록도 모두 지워지기를 원한다.

- **R4.1** 회원 탈퇴 시, 그 사용자의 책·회차·세션·독서 인증을 모두 삭제한다. (문장·리뷰·독후감은 지금처럼 review 쪽 탈퇴 정리에서 지운다)
- **R4.2** 탈퇴가 실패하면, reading 데이터도 지워지지 않는다 (기존 리스너와 같은 트랜잭션).

### R5. 검사와 문서

- **R5.1** `python3 scripts/harness/contract-check.py` 불일치 0건을 유지한다.
- **R5.2** 작업이 끝나면 ISSUE-BUG-1·ISSUE-BUG-2·ISSUE-DATA-1·ISSUE-DATA-2를 해결로 옮기고, 아래 "남는 경우"를 known-issues에 새로 기록한다.
