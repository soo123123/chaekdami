# 004 · 독서 인증 앱 연결과 사진 인증 보상 — Requirements

## 1. 배경

- 독서 인증 서버 API가 main에 들어왔다 (PR #13): `POST`·`GET /api/reading-records/{id}/certifications`. 사진을 AI가 읽고 `PASSED` · `UNVERIFIED` · `FAILED`로 판정한다. → [reading/api](../../domains/reading/api.md#독서-인증), [reading/rules](../../domains/reading/rules.md#5-독서-인증)
- 앱은 아직 옛 주소 `POST /api/reading-photos/verify`를 기준으로 만들어져 있고, `PHOTO_VERIFY_USE_MOCK = true`라서 사진을 서버로 보내지 않고 **항상 통과**를 돌려준다. → [TODO-1](../../known-issues.md#todo-1), 앱 `photoVerifyApi.ts`
- 그래서 `contract-check.py`에 불일치 1건이 계속 남아 있다.
- 사진 인증은 독서 종료 화면에서 **선택**이다. 사진을 붙이는 순간 검증하고, 통과하지 못하면 사진을 지우고 다시 찍게 한다 (`useReadingEnd.attachPhoto`). 이 흐름은 유지한다.
- 앱은 통과한 인증 번호를 세션 저장 요청(`photoVerificationId`)에 싣지만 서버에 받을 칸이 없어 버려진다 ([TODO-2](../../known-issues.md#todo-2)). 보상 쪽 사진 인증 확인(`PhotoCertificationChecker`)은 임시 구현이라 항상 "인증 안 됨"이다 ([TODO-3](../../known-issues.md#todo-3)). 독서 완료 화면의 사진 보너스 표시는 이미 있다 (스펙 001).
- 인증 기록은 회차에 붙는다. 다회독 첫 세션은 사진을 붙일 때 새 회차가 아직 없어서(저장 때 생성) 이전 회차에 붙는다. 보상은 세션 단위라 인증을 **세션에 직접 연결**하면 이 어긋남은 영향이 없다.

사람 결정 (2026-11-22):
- 쪽 번호는 너그럽게: 못 찾거나 읽은 범위와 달라도 넘어간다.
- 글자가 충분히 읽히지 않으면 다시 찍게 한다.
- 검증 시점은 지금처럼 사진을 붙이는 순간.
- AI 호출이 실패하면 서버가 한 번 다시 시도한다 (아래 R4). 사용 한도 초과(429)는 Gemini가 임시 API라 **통과**로 본다 (아래 R4.3).
- (승인 뒤 변경) 처음엔 보상 연결을 보류했으나, 다회독 회차 어긋남을 회차 옮기기로 푸는 대신 **인증을 세션·보상에 바로 연결**한다 (아래 R5).
- (승인 뒤 변경) 429로 통과한 인증은 **보상을 주지 않는다**. 정식 AI API로 바꾸면 의미가 없어지는 임시 규칙이다.

## 2. 요구사항

### R1. 실제 서버로 인증

사용자로서, 독서 인증 사진이 실제로 확인되기를 원한다.

- **R1.1** 독서 종료 화면에서 사진을 붙이면, 그 책의 **가장 최근 회차**로 서버 인증 API에 사진을 보낸다 (Mock을 쓰지 않는다).
- **R1.2** 인증 요청에는 읽은 쪽 범위를 보내지 않는다. 그래서 사진의 쪽 번호가 읽은 범위와 달라도 결과에 영향이 없다.
- **R1.3** 사진은 지금처럼 크기를 줄여서 보낸다.
- **R1.4** 사진이 통과하면, 서버가 준 인증 번호(`id`)를 지금처럼 세션 저장 요청의 `photoVerificationId`에 실어 보낸다.

### R2. 판정 결과 보여주기

사용자로서, 사진이 통과했는지와 다시 찍어야 하는 이유를 알고 싶다.

- **R2.1** 결과가 `PASSED`면, 사진을 통과로 표시하고 저장할 수 있게 한다.
- **R2.2** 결과가 `FAILED`면(책 페이지 아님, 같은 사진 재사용), 사진을 지우고 서버가 준 안내 문구를 보여준다.
- **R2.3** 결과가 `UNVERIFIED`면(글자가 충분히 읽히지 않음), `FAILED`와 똑같이 사진을 지우고 다시 찍게 안내한다.
- **R2.4** 서버 안내 문구가 없으면, 지금 쓰는 기본 문구를 보여준다.
- **R2.5** `PASSED`일 때 서버가 함께 준 참고 문구(쪽 번호 못 찾음, AI 확인 없이 통과 등)는 보여주지 않는다.

### R3. 기다리는 시간과 오류

- **R3.1** 서버가 AI 응답을 기다리는 전체 시간(R4.5, 약 40초)보다 앱이 먼저 포기하지 않는다. 앱이 기다리는 시간은 약 45초로 한다 (지금 15초).
- **R3.2** 시간이 넘거나 네트워크·서버 오류가 나면, 지금처럼 사진을 지우고 오류 안내를 보여준다.

### R4. AI 호출 다시 시도와 한도 초과 (서버)

사용자로서, AI가 잠깐 응답하지 못했다는 이유로 사진을 다시 찍고 싶지 않다.

- **R4.1** Gemini 호출이 **연결 실패** 또는 **서버 오류(5xx)** 로 끝나면, 서버가 **1초** 쉬고 **한 번만** 다시 부른다 (최대 2번 호출).
- **R4.2** 응답 대기 시간 초과(30초)로 끝나면 다시 시도하지 않는다.
- **R4.3** 사용 한도 초과(429)면 다시 시도하지 않고 `PASSED`로 판정한다. 임시 API라서 사용자를 막지 않기 위한 임시 규칙이다.
- **R4.4** R4.3으로 통과한 인증은 서버가 "AI 확인 없이 통과"로 구분해 저장하고, 안내 문구에도 남긴다. 앱에는 보여주지 않는다 (R2.5). 보상에서 걸러내기 위함이다 (R5.3).
- **R4.5** 첫 호출부터 따져 약 **40초** 안에 끝나지 못할 것 같으면 다시 시도하지 않는다. 첫 호출이 최대 35초(연결 5초 + 응답 30초)까지 걸릴 수 있으므로, 실제로는 첫 실패가 약 4초 안에 날 때만 다시 시도한다 (예: 10초 뒤 5xx면 다시 시도하지 않음).
- **R4.6** 그 밖의 실패(응답 형식 오류 등)는 다시 시도하지 않는다.
- **R4.7** 429가 아닌 실패에서 다시 시도해도 실패하면 지금처럼 `UNVERIFIED`를 주고, 앱은 R2.3대로 다시 찍게 안내한다.

### R5. 인증을 세션에 연결하고 보상 주기 (서버)

사용자로서, 사진 인증을 통과하고 저장하면 추가 경험치(+20 EXP)를 받고 싶다.

- **R5.1** 세션을 저장할 때 `photoVerificationId`가 오면, 그 인증이 **내 인증**이고 **`PASSED`** 이고 **아직 다른 세션에 쓰이지 않았으면** 이번 세션에 연결한다. 회차가 달라도(다회독 첫 세션) 연결한다.
- **R5.2** 조건에 맞지 않으면(없는 번호, 남의 인증, 통과 못 함, 이미 쓰임) 연결하지 않고, 세션 저장은 그대로 성공한다.
- **R5.3** 독서 완료 보상에서 "사진 인증된 세션"은 **연결된 `PASSED` 인증이 있고, 그 인증이 AI 확인 없이 통과(R4.3)한 것이 아닌** 세션이다. 이때 지금 보상 규칙대로 +20 EXP를 준다 (금액·중복 지급 규칙은 바꾸지 않는다).
- **R5.4** 인증 하나는 세션 하나에만 연결된다. 같은 번호로 여러 세션에서 보상을 받을 수 없다.

### R6. 검사와 문서

- **R6.1** `python3 scripts/harness/contract-check.py`를 실행하면 불일치가 0건이다.
- **R6.2** 작업이 끝나면 다음을 문서에 반영한다.
  - [known-issues](../../known-issues.md): TODO-1·TODO-3을 해결로 옮기고, TODO-2는 남은 부분(`photos` 저장 안 함)만 남긴다. ASK-5에 이번 결정(쪽 번호 너그럽게)을 반영한다.
  - [known-issues](../../known-issues.md): 새 할 일 2개를 기록한다 — 정식 AI API로 바꿀 때 R4.3(429 통과)·R5.3(429 보상 제외) 되돌리기, AI 장애를 `UNVERIFIED`와 구분해서 앱에 알려주기.
  - [reading/rules](../../domains/reading/rules.md#5-독서-인증): "AI 장애" 줄을 R4에 맞게 고치고, 세션 연결 규칙(R5.1, R5.2, R5.4)을 넣는다.
  - [reward/rules](../../domains/reward/rules.md#2-경험치): 사진 인증 추가 경험치를 ✅로, R5.3 기준을 적는다.

## 3. 범위 밖

- R4(AI 호출 다시 시도, 429 통과) 외의 서버 판정 규칙 변경
- 사진 인증 보상 금액·지급 규칙 변경 (+20 EXP, 세션당 1번 그대로)
- 인증 기록의 회차를 새 회차로 옮기기 — 보상은 세션 연결로 판단하므로 하지 않는다. 다회독 첫 세션의 인증은 이전 회차에 남는다
- 정식 AI API로 바꿀 때 R4.3·R5.3의 429 임시 규칙을 되돌리는 일 — 나중에 (R6.2에서 할 일로 기록)
- AI 장애를 `UNVERIFIED`와 구분해서 앱에 알려주기 — 나중에 (R6.2에서 할 일로 기록)
- 인증 요청에 문장 보내기 (사진을 붙이는 시점에는 문장이 아직 없을 수 있음)
- 인증 목록 화면 (`GET` API는 이번에 앱에서 쓰지 않는다)
- 사진 파일 저장 (세션 요청의 `photos`)
