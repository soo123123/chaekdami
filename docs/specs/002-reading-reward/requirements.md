# 002 · 독서 보상 연결 — Requirements

> 범위: FE1 독서 종료 → FE2 독서 완료 화면 → BE2 보상 파트 연결
> 담당: FE1(독서 종료·세션 저장), FE2(독서 완료 화면), BE2(보상), BE1(사진 인증 — 이번엔 자리만)

## 1. 배경 (현재 상태, 2026-11-22 기준 fix/fe1)

- 세션 저장(`POST /api/reading-sessions`) 시 `ReadingSessionService.create()`가 `questService.recordReadingSession()`을 호출해
  **퀘스트 진행도 반영 + 달성 퀘스트 보상 자동 지급**이 저장 시점에 일어난다.
- 독서량 경험치·스트릭을 함께 지급하는 `ReadingSessionRewardService.grant()` / `ReadingSessionRewardHook`은 구현돼 있으나
  **호출하는 곳·API가 없다** → 독서 경험치는 지급되지 않는다.
- 독서 완료 화면(`useReadingComplete`)은 `GET /api/rewards`, `GET /api/quests`만 호출하고,
  "획득 경험치"는 프론트가 퀘스트 보상을 더해 추정한다. 값이 없으면 시안 예시 값을 쓴다.
- 스트릭이 두 군데서 관리된다: 저장 시 `DdayService.markTodayRead()`, 보상 쪽 `StreakService.recordReadingDay()`(현재 미호출).

## 2. 목표

독서 1세션의 보상(독서 경험치·퀘스트 보상·스트릭·레벨업 승급 보상, 이후 사진 인증 보너스)을
**독서 완료 화면에서 한 번에, 정확히 한 번만** 지급하고, 그 실제 결과를 화면에 그대로 보여준다.

## 3. 결정 사항

| # | 항목 | 결정 | 근거 |
|---|------|------|------|
| D1 | 지급 시점 | 완료 화면 **진입 시 자동** POST (버튼 없음) | 사용자 동작에 의존하지 않아 미수령 경우가 적음 |
| D2 | 중복 방지 | 세션 단위 **멱등** — 두 번째 호출은 저장된 결과를 그대로 반환(에러 아님) | 재진입·재시도·더블 호출이 모두 안전 |
| D3 | 미수령 보상 | 세션을 `PENDING`으로 남기고 **서버가 나중에 정산** (`GET /api/rewards` 등에서) | 앱 종료·네트워크 실패에도 보상 손실 없음 *(가정 — 확인 필요)* |
| D4 | "독서 사실" vs "보상" 분리 | 퀘스트 **진행도**·스트릭 **기록**은 저장 시점, **재화·경험치 지급**은 완료 화면 시점 | 정산이 다음 날로 밀려도 날짜가 틀어지지 않음 |
| D5 | 사진 인증 보너스 | 응답·세션에 **필드 자리만** 두고 금액 0 — BE1 검증 API 완성 후 활성화 *(가정)* | BE1 검증 API·세션 필드 미구현 |

## 4. 요구사항

### R1. 세션 저장 (FE1 → reading)
- R1.1 세션을 저장하면 서버는 그 세션의 보상 상태를 `PENDING`으로 기록한다.
- R1.2 세션 저장 시 오늘 퀘스트 **진행도**와 스트릭 **기록**을 반영하되, 재화·경험치는 **지급하지 않는다**.
- R1.3 저장 응답에는 세션 번호(`id`)가 포함되고, FE1은 이를 완료 화면에 `sessionId`로 넘긴다.
- R1.4 보상 쪽 처리에 실패해도 독서 기록 저장은 실패하지 않는다(보상은 PENDING으로 남아 이후 정산).

### R2. 보상 지급 (FE2 → BE2)
- R2.1 완료 화면은 진입 시 `POST /api/reading-sessions/{sessionId}/reward`를 **한 번** 호출한다.
- R2.2 서버는 `PENDING`이면 지급 후 `GRANTED`로 바꾸고 결과 스냅샷을 저장해 반환한다.
- R2.3 이미 `GRANTED`면 다시 지급하지 않고 저장된 스냅샷을 `alreadyGranted: true`와 함께 반환한다.
- R2.4 동시에 두 번 호출돼도 지급은 한 번만 일어난다.
- R2.5 다른 사용자의 세션이면 404를 반환한다.
- R2.6 지급 항목: 독서 경험치(부스터 반영), 달성·미수령 퀘스트 보상, 레벨업 승급 보상, (D5) 사진 보너스.
- R2.7 응답만으로 완료 화면의 D-day·레벨·경험치 바·획득 경험치·퀘스트 보상·코인 카드를 그릴 수 있어야 한다.

### R3. 완료 화면 표시 (FE2)
- R3.1 "획득 경험치"·"오늘의 보상 코인"은 R2 응답 값을 그대로 쓴다(프론트 추정 제거).
- R3.2 지급 요청 중에도 화면은 바로 그리고, 보상 카드만 로딩 상태로 둔다.
- R3.3 지급 요청이 실패하면 보상 카드에 "다시 시도"를 보여주고, 실패해도 다른 영역·독후감 버튼은 정상 동작한다.
- R3.4 `alreadyGranted: true`면 같은 값을 보여주되 획득 연출(애니메이션·토스트)은 생략한다.
- R3.5 `sessionId` 없이 연 경우(미리보기 등)는 지급 호출 없이 기존 조회(GET)만 한다.
- R3.6 레벨업(`level > levelBefore`)이면 레벨업 표시를 한다.

### R4. 미수령 정산 (BE2)
- R4.1 `GET /api/rewards` 호출 시 해당 사용자의 `PENDING` 세션을 먼저 정산한다.
- R4.2 정산 결과는 R2와 같은 스냅샷으로 저장해, 나중에 그 세션의 완료 화면을 열어도 같은 값이 나온다.

### R5. 정리
- R5.1 스트릭 증가는 한 곳에서만 일어난다(`DdayService`와 `StreakService` 중복 해소 — BE2 확인).
- R5.2 기존 `POST /api/quests/{id}/reward`는 호환용으로 유지한다.

## 5. 비기능
- 보상 지급은 보상 계정 행 잠금(`RewardLedger.lockAccount`) + 세션 보상 행 잠금으로 직렬화한다.
- 완료 화면의 지급 요청 타임아웃은 공용 기본값(10초)을 따른다.

## 6. 범위 밖

- 보상 카드 애니메이션 디자인
