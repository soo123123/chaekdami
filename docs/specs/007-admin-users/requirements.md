# 007 · 관리자 사용자 관리 — Requirements

## 1. 배경

- 관리자 API는 리뷰 신고 목록과 블라인드 2개뿐이다 (`ReviewAdminController`, [TODO-10](../../known-issues.md#todo-10)). `/api/admin/**`는 `ADMIN` 역할만 부를 수 있다 (`SecurityConfig`).
- `users`에는 `role`(USER·ADMIN), `token_version`, `created_at`만 있고 계정 상태가 없다 ([user/data](../../domains/user/data.md#users)). 문제를 일으킨 사용자를 막을 방법이 없다.
- 사용자를 `ADMIN`으로 바꾸는 코드가 없다. 지금은 DB를 직접 고쳐야 한다.
- 역할은 Access Token 안에 들어 있다. 필터는 요청마다 `token_version`을 DB와 비교해 다르면 401로 막는다 ([user/rules §2](../../domains/user/rules.md#2-토큰)). 버전을 올리면 이미 발급된 토큰을 바로 무효로 만들 수 있다.
- 목록 페이지 번호는 review 관리자 API와 같이 0부터 시작한다 (`PageResponse`). 통일 여부는 [ASK-3](../../known-issues.md#ask-3).
- 사람 결정 (2026-11-23): 관리자 화면은 만들지 않고 http 요청으로만 쓴다. 범위는 회원 목록·검색·상세, 이용 정지·해제, 역할 변경. 정지는 끝 시각을 정할 수 있고(비우면 무기한), 정지 사유를 저장해 관리자만 본다. 정지된 사용자의 로그인은 `403 ACCOUNT_SUSPENDED`로 응답한다. 정지된 사용자도 비밀번호 재설정은 할 수 있다. 관리자는 다른 관리자를 정지하거나 역할을 바꿀 수 없다.

## 2. 요구사항

### R1. 권한

- **R1.1** 관리자가 아닌 사용자가 이 스펙의 API를 부르면, `403 FORBIDDEN`으로 응답하고 아무것도 바꾸지 않는다.
- **R1.2** 로그인하지 않고 부르면, `401`로 응답한다.

### R2. 회원 목록·검색

관리자로서, 문제 사용자를 찾기 위해 회원을 검색하기를 원한다.

- **R2.1** 관리자가 목록을 조회하면, 회원 번호·이메일·닉네임·역할·상태·정지 끝 시각·가입일을 가입일 최신순으로 페이지 단위로 돌려준다.
- **R2.2** 검색어를 주면, 이메일이나 닉네임에 검색어가 들어간 회원만 돌려준다 (대소문자 무시).
- **R2.3** 역할이나 상태를 주면, 그 값인 회원만 돌려준다.
- **R2.4** 응답에 비밀번호 해시·토큰 같은 인증 정보는 들어가지 않는다.

### R3. 회원 상세

- **R3.1** 관리자가 회원 번호로 조회하면, 목록 항목에 더해 정지 사유·정지 시각·정지한 관리자 번호를 돌려준다.
- **R3.2** 없는 회원 번호면, `404 USER_NOT_FOUND`로 응답한다.

### R4. 이용 정지

관리자로서, 문제 사용자가 서비스를 쓰지 못하게 하기를 원한다.

- **R4.1** 관리자가 회원을 정지하면, 그 회원의 상태가 정지가 되고 사유(선택)·끝 시각(선택)·정지 시각·정지한 관리자가 기록된다.
- **R4.2** 정지하면, 그 회원이 이미 받은 Access Token과 Refresh Token이 바로 쓸 수 없게 된다 (다음 요청부터 401).
- **R4.3** 정지된 회원이 올바른 비밀번호로 로그인하면, `403 ACCOUNT_SUSPENDED`로 응답하고 정지 끝 시각(무기한이면 null)을 알려준다. 토큰은 발급하지 않는다.
- **R4.4** 비밀번호가 틀리면, 정지 여부와 관계없이 지금과 같이 `401 INVALID_CREDENTIALS`로 응답한다 (정지 사실을 드러내지 않는다).
- **R4.5** 끝 시각이 지나면, 관리자가 해제하지 않아도 그 회원은 로그인할 수 있다.
- **R4.6** 끝 시각을 지금보다 이전으로 주면, `400 VALIDATION_ERROR`로 응답한다.
- **R4.7** 이미 정지된 회원을 다시 정지하면, 사유와 끝 시각을 새 값으로 바꾼다.
- **R4.8** 정지된 회원도 비밀번호 재설정 요청·재설정을 할 수 있다. 재설정해도 정지는 풀리지 않는다.

### R5. 정지 해제

- **R5.1** 관리자가 정지를 해제하면, 그 회원은 바로 로그인할 수 있다. 정지 사유·끝 시각은 지운다.
- **R5.2** 정지되지 않은 회원을 해제하면, 아무것도 바꾸지 않고 성공으로 응답한다.

### R6. 역할 변경

- **R6.1** 관리자가 회원의 역할을 `USER`나 `ADMIN`으로 바꾸면, 그 값으로 저장된다.
- **R6.2** 역할을 바꾸면, 그 회원의 기존 토큰이 바로 쓸 수 없게 되어 다시 로그인해야 새 역할이 적용된다.
- **R6.3** 지금 역할과 같은 값으로 바꾸면, 아무것도 바꾸지 않고 성공으로 응답한다 (토큰도 그대로).

### R7. 관리자 보호

- **R7.1** 관리자가 자기 자신을 정지하거나 자기 역할을 바꾸려 하면, `400`으로 응답하고 아무것도 바꾸지 않는다.
- **R7.2** 대상 회원이 `ADMIN`이면, 정지와 역할 변경을 `400`으로 거절하고 아무것도 바꾸지 않는다. 관리자를 정지하거나 내리려면 DB에서 직접 역할을 바꾼다.
- **R7.3** 대상이 `ADMIN`이어도 정지 해제는 할 수 있다 (DB에서 정지된 관리자를 풀 수 있게).

### R8. 문서

- **R8.1** 구현이 끝나면, `docs/domains/user/`(api·rules·data·overview)에 관리자 API와 정지·역할 규칙이 반영되고 TODO-10 표시가 지워진다. `backend/http/`에 요청 예시가 있다.

## 3. 범위 밖

- 관리자 화면(앱·웹)
- 강제 탈퇴
- 회원 상세의 활동 요약 (리뷰 수·신고받은 수·독서 기록 등 다른 도메인 데이터)
- 정지·해제 알림 메일, 정지 이력 보관 (마지막 정지 정보만 남김)
- 정지된 회원의 데이터(리뷰 등) 숨김
- 첫 관리자 만들기 (지금처럼 DB에서 직접 지정)
