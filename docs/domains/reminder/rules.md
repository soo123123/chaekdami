# reminder 규칙

알림 규칙은 모두 앱의 `buildReminderPlan.ts`에 있다. 서버는 값만 준다.

## 1. 알림 목록

| # | 알림 | 시각 | 보내는 조건 | 제목 / 본문 |
|---|---|---|---|---|
| 1 | 저녁 | 20:00 | 오늘 안 읽음 | 오늘 한 페이지만 읽어볼까요? |
| 2 | 연속 독서 | 21:30 | 오늘 안 읽음, 연속 2일 이상 (방어권과 관계없이) | 책다듬이가 {닉네임}님을 찾고 있어요 / N일 연속 독서가 이어지려면 오늘 10분만 읽어요! |
| 3 | 복귀 | 20:00 | 8·14·30일째 미접속 | 단계별 문구 (아래) |
| 4 | 주말 아침 | 토 09:00 (토요일에 안 읽었으면 일 09:00) | 오늘 안 읽음 | 여유로운 주말 아침, 책 한 장 어떠세요? |
| 5 | 주간 목표 임박 | 19:00 | 이번 주 목표까지 60분 이하, 주 1회 | 책다듬이가 {닉네임}님을 찾고 있어요 / 이번 주 목표까지 N분 남았어요! 조금만 더 읽어볼까요? |
| 6 | 주간 마무리 | 일 18:00 | 항상. 달성하면 축하, 아니면 독려 | 책다듬이가 {닉네임}님을 찾고 있어요 / 이번 주 H시간 M분 읽었어요. 목표 달성! … 또는 이번 주 목표까지 N분 남았어요. … |
| 7 | 미접속 | 20:00 | 2·4·6일째 미접속 | 단계별 문구 (아래) |

| 규칙 | 값 | 코드 위치 |
|---|---|---|
| 제목 | 문구가 25자(공백 포함) 이하면 제목으로만, 길면 "책다듬이가 {닉네임}님을 찾고 있어요" + 본문 | `reminderMessages.toContent` |
| 금지 시간 | 22:30~08:00에는 보내지 않음 | `buildReminderPlan.isQuiet` |
| 하루 개수 | 제한 없음 | — |
| 숫자 | 예약할 때 계산. 내일 값은 오늘 더 읽지 않는다고 보고 계산 (연속은 방어권이 있을 때만 이어짐) | `buildReminderPlan` |
| 지난 시각 | 예약할 때 이미 지난 알림은 만들지 않음 | `buildReminderPlan` |
| 알림 끔 | 아무것도 예약하지 않음 | `buildReminderPlan` |
| 이른 아침·늦은 저녁 끄기 | 4번·2번을 예약하지 않음 | `buildReminderPlan.buildDay` |

미접속·복귀 단계별 문구 (시무룩 → 서운함 → 삐짐 → 화남 → 포기): `reminderMessages.ABSENCE_STAGES`. 30일째 뒤로는 보내지 않는다.

## 2. 겹침 규칙

| # | 규칙 | 내용 |
|---|---|---|
| ① | 더 구체적인 알림이 대신함 | 2번이 가는 날, 7·3번이 가는 날에는 1번을 보내지 않음 |
| ② | 주 1회 | 5번은 조건이 처음 맞는 날 한 번. 일요일에는 6번이 대신함 |
| ③ | 주말 아침은 주말에 1번 | 4번은 토요일, 토요일에 안 읽었을 때만 일요일 |
| ④ | 미접속이 길면 매일 알림 중단 | 마지막 접속 다음 날까지 평소대로, 2일째부터 7번만, 8일째부터 3번만 |
| ⑤ | 같은 날 최소 간격 1시간 | 1시간 안에 겹치면 우선순위(7·3 > 2 > 6 > 5 > 1 > 4)가 낮은 쪽을 뺌 |

앱을 열 때마다 다시 예약하므로 매일 알림(1·2·4·5·6번)은 오늘과 내일만, 그 뒤는 7·3번만 예약한다. 한 번에 최대 약 15개.

## 3. 다시 예약과 취소

| 언제 | 처리 | 코드 위치 |
|---|---|---|
| 앱 시작, 화면 복귀 | 다시 예약 | `ReminderSync` |
| 로그인, 가입 | 다시 예약 | `LoginScreen`, `SignupScreen` |
| 독서 시작 | 오늘의 1·2·4번 취소. 독서 화면이 열려 있는 동안 다시 만들지 않음 | `ReadingStartScreen` → `markReadingStarted` |
| 독서 저장 성공, 독서 화면 벗어남 | 다시 예약 | `useReadingEnd`, `ReadingStartScreen` → `markReadingStopped` |
| 보상 처리 성공 | 다시 예약, 처음이면 알림 권한 요청 | `useReadingComplete` |
| 설정 저장 | 다시 예약 | `NotificationSettingsScreen` |
| 토큰 삭제 (로그아웃·탈퇴·세션 만료·재발급 실패) | 우리 알림 모두 취소 | `tokenStorage.onTokensCleared` → `ReminderSync` |
| 조회 실패·오프라인 | 기존 예약 유지 | `reminderScheduler` |
| 권한 없음 | 예약하지 않음. 설정 화면에 안내 | `reminderScheduler`, `NotificationSettingsScreen` |

- 우리 알림만 identifier `reminder:`로 골라 지운다
- 다시 예약이 겹치면 진행 중인 것이 끝난 뒤 한 번만 더 실행한다
- 앱을 보고 있을 때 온 알림은 표시하지 않는다
- Android 채널(`reading-reminder`)을 만들지 못하면(Expo Go) 권한 요청·예약은 계속하고 기본 채널로 예약한다
- Android 정확한 알람 권한은 쓰지 않아 몇 분 늦을 수 있다. 강제 종료·절전으로 빠지는 알림은 알려진 한계
- 개발용: `__DEV__`에서 `EXPO_PUBLIC_REMINDER_DAY_SECONDS`가 있으면 하루를 그 초로 줄여 예약한다

## 4. 날짜 기준

| 규칙 | 값 | 코드 위치 |
|---|---|---|
| 오늘·주 | 한국 날짜, 주는 월요일 0시 시작. 서버 시간대와 관계없음 | `ReminderWeek` |
| 독서 날짜 | 세션 종료 시각 기준. 자정을 넘긴 독서는 끝난 날 | `ReminderStatusService` |
| 방어권 정산 기준일 | 한국 날짜의 오늘 | `StreakServiceReminderReader` |
| 알림 시각 | 기기 시간대로 예약 (한국 사용자 기준) | `buildReminderPlan` |

이 기준은 알림용 조회에만 쓴다. 다른 화면·API의 날짜 기준은 그대로다 (2026-11-28 결정).
