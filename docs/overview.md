# 서비스 개요

> 이 문서의 "기획 의도"는 캡스톤 계획서·초기 README에서 옮긴 것이다. **구현 여부는 각 표의 상태 칸과 [known-issues.md](./known-issues.md)를 본다.**

## 1. 한 줄 소개

**책다듬이 (Chaekdami)** — 연속 달성과 보상(게이미피케이션)으로 꾸준한 독서와 독후 활동을 돕는 모바일 독서 앱.

| 항목 | 내용 |
|---|---|
| 과제 | 캡스톤디자인 B조, 2026-09-07 ~ 2026-12-14 |
| 앱 | React Native (Expo) |
| 서버 | Spring Boot 4.1, Java 21 |
| DB | PostgreSQL (Supabase) |
| 외부 | YES24 Open API (도서), Gmail SMTP (메일) |

## 2. 왜 만드나 (기획 의도)

- 성인 연간 종합독서율이 38.5%로 역대 최저 (2025 국민독서실태조사).
- 청소년 94.2%가 숏폼을 이용하고, 짧은 자극에 익숙해져 독서처럼 깊은 사고가 필요한 자극에 반응하기 어려워진다("팝콘 브레인").
- 듀오링고처럼 **연속 달성과 보상**에서 동기를 얻어 독서를 이어가게 한다.
- 간단한 기록 방식으로 초보자도 부담 없이 시작하고, 독서량·완독률·취향을 시각화해 성과를 체감하게 한다.

## 4. 사용자 흐름

```
로그인 → 홈
  ├─ 서재 → 책 추가(검색/직접) → 서재
  ├─ 서재 → 책 상세 → 독서(타이머) → 독서 종료(시간·페이지·문장) → 독서 완료(보상·퀘스트·연속일)
  │                                                                 └─ 완독이면 → 독후감·별점·한줄평
  ├─ 커뮤니티 (완독한 책)
  ├─ 보상 / 퀘스트 / 상점 / D-day
  └─ 마이페이지 / 독서 통계
```

## 5. 사용자 유형

| 유형 | 할 수 있는 것 |
|---|---|
| 비회원 | 로그인·가입·비밀번호 찾기 화면만. 나머지 화면은 로그인으로 이동 |
| 일반 사용자 (`USER`) | 위 기능 전부 |
| 관리자 (`ADMIN`) | 일반 기능 + 신고 리뷰 목록·블라인드 처리, 회원 조회·정지·역할 변경 (API만) |

## 6. 도메인 구조

```
책다듬이
├── reading  독서 — 책, 서재, 독서 기록(회차), 세션, 독서율, 통계
├── review   독후 활동 — 문장 모음, 리뷰(별점·한줄평), 독후감, 커뮤니티
├── reward   보상 — 경험치·레벨, 재화, 퀘스트, 상점, 부스터
├── dday     연속 독서 — D-day 목표, 달력, 방어권
└── user     사용자 — 회원, 인증, 권한
```

초기 기획에는 "서재(꾸미기)"와 "랭킹"이 별도 영역으로 있었다. 지금은 서재가 reading에 포함되고, 꾸미기는 서버 구현이 없고, 랭킹은 reward의 주간 랭킹 API(경험치·독서 시간)로 있다 (화면은 TODO-6).
